
Zoltan: Ans on Fiscal Block

let me send below my reactions to the issues raised so far.
First of all, I'm attaching updated codes, which should address all points except those related to readData_new.
In particular, the new forecast report table with the auxiliary variables is included.
I also removed setparam1/2/3, they were intended for experimentation only.
The supplemtables code is updated as well.
Also, the trend/gap decompositions are fine in both the historical and the forecast report. The trick is the use the addTrendsAndGaps function with correct inputs (line 266 of reportForecast). This basically means that when we're preparing the forecast report, the "observed" data is taken from the forecast database just as in Arend's version, but this solution works for both reports.
The second decomposition of the deficit ratio is indeed a bit tricky, but can be solved without adding a new model variable, see lines 732-751 in addDecompositions (743 and 745 in particular). Basically, the seriesName variable does not actually have to refer to an existing model variable, it's more like the name of the decomposition; in 99% of the cases this is indeed the name of a model variable, but there are exceptions (the UIP decomposition in lines 403-423 is another one).
There was a question about how to best save table data. The easiest way (and the only one which does not require substantial additional effort) is to collect the data in an IRIS database, and use the toCSV method. Anything else needs a bit of extra work.

grev_y_cyc = v1⟨0.042⟩ * l_cons_gap + v2⟨0.021⟩ * l_imp_gap + v3⟨0.07⟩ * l_y_gap + shock_grev_y_cyc⟨σ=0⟩ (B)
